# 실행·계정·보관 안내

## 시작
Node.js 24 LTS 사용. 이 PC에서 확인한 버전은 24.19.0. 추가 유료 서비스나 API 키는 필요 없다.

```powershell
npm ci
npx playwright install chromium
npm run build
npm start
```

브라우저에서 http://127.0.0.1:4173 을 연다. 개발은 `npm run dev`. 서버를 종료하면 새 요청·로그인·저장·출력은 멈추지만 이미 저장한 DB는 유지된다.
포트 4173 사용 중이면 기존 HRBIP 프로세스를 종료하거나 .env.local의 PORT와 APP_ORIGIN을 함께 변경한다. 예시는 .env.example에 있다.

## 권장 확인 흐름
1. 홈 → 샘플로 체험하기. 로그인 없이 결과·편집·출력 체험.
   홈의 **샘플 목록**에서는 사용자 제공 **150명·24개월 샘플**도 선택할 수 있다. 상세 기준은 SAMPLES.md 참고.
2. 내 자료로 시작하기 → CSV/XLSX 선택 → 시트·헤더 선택 → 역할·항목·단위 연결.
3. 문제를 수정하거나 해당 표를 보류. 기간·완전 이력·퇴사일 기준을 확인.
4. 추천 결과 생성 → 필터/차트 탐색 → 필요하면 구성·보고 문장 편집.
5. 최종 확인·내보내기에서 문장과 숫자를 함께 확인. PDF/PPTX/Excel 선택.
6. 계정 만들기 → 저장 → 저장한 작업에서 다시 열기.
7. 구성 템플릿 저장 → 새 데이터 적용. 이전 직원 정보·수치는 가져오지 않음.
8. 최종 확인 → 공유 → 상대방이 내 계정에서 복사한 계정 ID 추가. 링크는 권한을 대신하지 않음.

## 인증
실제 로컬 계정 저장 + 비밀번호 scrypt 해시 + 난수 세션 토큰의 SHA-256 저장.
HttpOnly/SameSite=Strict 쿠키, 12시간 만료, 로그아웃 시 서버 세션 삭제. 비밀번호 평문은 보관하지 않는다.
아이디는 영문·숫자·._- 3~32자, 비밀번호 10~128자. 이메일 주소 소유 여부를 주장하지 않는 계정 ID 방식이다.
이메일 인증·비밀번호 찾기·MFA·SSO는 현재 없음. 테스트 계정은 자동 테스트 전용 DB에만 생성.
실제 사용자 계정은 사용자가 웹에서 직접 만든다.

## 데이터 위치와 생명주기
기본 저장 파일: `.data/hrbip.sqlite`. 사용한 원본 파일도 별도 공개 폴더가 아니라 DB BLOB으로 보관한다.
비로그인: 업로드·수정 데이터는 브라우저 메모리에만 존재. 탭 종료/새로고침으로 소멸하며 경고를 표시한다.
규칙 기반 계산·시각화는 브라우저에서 수행. 저장/내보내기 시 이 PC 서버로 필요한 자료가 전송된다. 외부 AI 전송 없음.
로그인 후 저장: 연결한 표준 항목의 분석 데이터, 기준, 필터, 디자인, 보고 문장, 변경 기록을 저장한다. 연결하지 않은 이름·연락처 등 열은 저장하지 않는다.
원본 보관 선택: 선택한 경우 파일 전체가 보관될 수 있다. 선택하지 않은 시트/열의 정보도 원본 파일 안에는 있으므로 이를 포함해 판단해야 한다.
원본 미보관은 분석 데이터 미보관이 아니다.
작업 삭제: 작업·분석 데이터·원본·공유 권한 함께 삭제. 템플릿은 별도 삭제.
SQLite secure_delete 활성화. 운영체제·디스크 백업 및 이미 내보낸 파일의 삭제까지 보장하지 않는다.
DB는 애플리케이션 수준에서 암호화하지 않는다. 이 PC 계정·디스크 접근 권한 관리가 필요하다.

## 공유 범위
같은 HRBIP 서버의 지정된 계정만 접근한다. 소유자: 수정/삭제/원본 조회/공유 관리. 수신자: 집계 조회/필터/집계 내보내기.
수신자에게 사번·개인별 인사·급여 행을 반환하지 않는다. 공유 필터는 서버에서 다시 계산한다.
필터 변경 시 수신자 화면에 현재 조건의 규칙 기반 초안을 표시하고, 기존 범위의 담당자 의견을 가져오지 않는다. 소유자의 문장은 덮어쓰지 않는다.
저장한 작업을 다시 저장하면 기존 공유 대상이 보는 내용도 갱신된다. 별도의 고정 스냅샷 공유 기능은 없다.
권한 해제는 다음 서버 요청부터 적용. 이미 다운로드한 파일이나 기존 브라우저 메모리까지 회수하지 않는다.
현재 127.0.0.1에만 바인딩하므로 다른 PC에서 접속할 수 없다. 외부 공개/계정 제공자 이전/유료 비용은 사용자 확인 후 별도 진행한다.

## 파일 지원
- UTF-8/EUC-KR CSV, XLSX 다중 시트. 최대 파일당 10MB·총 20MB·표당 10,000행·전체 30,000행·100열·24개 표.
- 헤더 위치 선택, 컬럼명 추천·수동 연결.
- 근태·급여의 여러 수치 열은 선택한 열별로 작업용 표로 변환 가능. 총계/세부 중복 합산을 사용자가 확인해야 한다.
- 행식 자료는 기록 ID 또는 사번+날짜+항목을 고유 키로 지정.
- XLSX 수식은 캐시된 결과만 사용. 없는 계산 결과는 재계산·저장 안내.
- XLS/XLSM/암호화, 병합 교차표, 다단 헤더, 자동 소계 제거, 임의 기업 양식의 무조건 해석은 지원하지 않는다.
- 현재 인사 명단 또는 재직 구간 이력을 지원한다. 월별 스냅샷을 자동으로 재직 구간으로 바꾸는 기능은 없음.
- 시간은 십진수 시간, 휴가는 십진수 시간/일. HH:mm 자동 변환 없음. KRW 원/천원/만원만 지원.
- 월 자료의 기준일은 해당월의 유효한 날짜로 연결한다. 귀속월 자료는 지급일 자료로 해석하지 않도록 사용자가 항목 의미를 확인한다.

## 출력
PDF: 한글 시스템 폰트 + Chromium, 선택 차트·보고서·수치 표. PDF 렌더러 설치는 위 Chromium 설치 명령으로 해결.
PPTX: 편집 가능한 텍스트·표·네이티브 차트+내장 XLSX. PowerPoint에서 확인함. 웹 필터는 포함되지 않음.
빈 시점이 있는 선그래프는 누락 구간을 0으로 만들지 않고 해당 시점을 제외한 막대로 출력하며 안내한다.
Excel: 집계표·기준·보고 문장·변경 기록. 개인별 원본 제외. 표시는 자료 없음 문구, 실제 숫자는 숫자 셀.
내보내기 전 보고서와 현재 데이터 기준의 확인 키가 일치해야 한다. 사람이 수정한 문장의 사실성 전체를 자동 검증한다고 주장하지 않는다.

## 기능 요청
홈 요청은 이 PC DB의 requests 표에 실제 저장한다. 외부 이메일 전송이나 공개 게시판 아님.
운영자가 필요하면 로컬 DB에서 확인 가능. 별도 관리자 UI는 만들지 않음.

## 실제 HR 자료 / 외부 공개 전 남은 검토
가상 자료로 검증했다. 외부 보안 감사, 침투 테스트, 실제 기업별 접근 권한·개인정보 처리 기준 검증은 수행하지 않음.
인터넷 운영에는 HTTPS, 배포 환경, 백업/복원·보관 기간 정책, 계정 복구, 접근 로그·모니터링·암호화 요구 검토가 필요.
이 목록은 로컬 기능을 미구현 버튼으로 대체한다는 뜻이 아니라 실제 서비스 운영 검토 범위다.
