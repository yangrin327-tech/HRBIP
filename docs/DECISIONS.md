# 구현 설계 결정 (2026-10-05)

1. 사용자의 새 제작 요청으로 구현 대기를 해제. 기간 제한 없이 연결된 1차 도구를 구현.
2. 사용자가 '내 컴퓨터에서 먼저 완성'을 확인. React/TypeScript + Express + Node 내장 SQLite. 외부 계정·요금 불필요. GitHub/배포 미실행.
3. 마지막 재직일을 퇴사일 기본값으로 사용자 확인. 작업별 변경 가능. 현재 명단과 완전 이력 모드를 분리.
4. 원본 파일은 브라우저에서 읽고, 작업용 행만 수정. 저장 때 매핑한 항목만 정리해서 보관. 원본 보관은 별도 선택.
5. 넓은 표는 수치 열을 선택해 세로 기록으로 펼침. 사용자의 원본 파일은 그대로 둠. 총액과 세부항목을 함께 더하지 말라는 안내 및 재확인.
6. 자료 없는 근태/지급 월은 null. 현재 인원 명단으로 과거를 만들지 않음. 재직 구간/기록 키/인사 연결 실패 시 해당 영역 계산 중단.
7. 하나의 shared/analytics.ts가 브라우저, 보고서, 서버 공유/내보내기의 계산 원천. 정규화한 정렬 키의 해시로 저장 후에도 기준 동일성 유지.
8. 데이터 키 변경 시 보고서를 덮어쓰지 않고 비교/갱신을 요청. 직접 편집한 문장을 보존하는 선택 제공. 외부 AI는 없음; rules provider interface 분리.
9. 비밀번호 해시 + 실제 세션으로 로그인. 공유는 공개 URL이 아닌 지정된 로컬 계정 ID의 ACL. 원시 분석 행은 소유자만 조회.
10. 수신자 필터 결과는 서버에서 계산. 필터 범위가 달라지면 규칙 초안을 새로 생성하고 소유자 기존 의견은 필터 결과에 재사용하지 않음.
11. PPTX는 화면 캡처 대신 네이티브 차트/표/텍스트. 누락 구간 연결을 피할 때 막대 대안을 안내. 축 기본값은 비음수 지표에서 0으로 통일.
12. 파일 읽기 라이브러리는 지연 로드. 의존성 보안 경고는 uuid 11.1.1 / image-size 2.0.4 override로 해소하고 실제 출력 시험. 이미지 추가 기능은 현재 출력 경로에 없음.
13. Git 작성자는 Codex <codex@local.invalid>로 로컬 커밋. 사용자 Git 신원을 임의 설정하지 않음.
14. 별도 작업에서 추가된 180명/24개월 합성 자료와 로그는 보존. 내장 샘플(48명/9개월)과 구분하며, 별도 자료의 퇴사일 제외 기준을 기본값으로 몰래 바꾸지 않음.
15. 입력 파일의 범용성은 명시한 데이터 계약 안에서 제공. 모든 회사 양식·모든 이력 모델 호환을 주장하지 않음.

## 2026-10-06 — 반복 보고와 검토 흐름
- 사용자 요청으로 홈 목적 설명, 입력 준비 안내, 새 자료 반복 보고, 지표별 계산 근거, 출력 전 내용 미리보기를 추가했다. 실제 회사에서 시간 절감·양식 적합성이 검증되었다고 주장하지 않는다.
- 반복 보고는 기존 작업을 수정하는 방식이 아닌 새 작업 생성이다. 재사용 계획에는 필드 연결과 해석 규칙만 넣으며 행·직원값·과거 보고 문장·이력 기간은 포함하지 않는다. 디자인 전용 템플릿의 기존 저장 계약은 변경하지 않는다.
- 항목 연결 후보는 필요한 열이 모두 있고 후보가 유일하거나 시트/펼친 항목 이름이 유일할 때만 추천한다. 선택이 끝나도 데이터 확인은 모두 해제되어 단위와 이력 범위를 재확인해야 한다. 없는 열은 자동으로 다른 열에 연결하지 않는다.
- 수치 계산은 기존 shared/analytics.ts를 유지한다. 설명은 shared/metric-evidence.ts, 반복 규칙은 shared/reuse.ts, 화면은 별도 컴포넌트로 분리했다.
- 미리보기는 동일 집계·유효 차트 구성·보고 문장을 보여준다. PDF/PPT는 선택 차트, Excel은 전체 집계표라는 차이를 표시한다. 파일별 페이지 조판을 그대로 재현하는 미리보기는 아니다.

## v0.1.4 회사 양식·검증 결정
- 기본 출력과 별도로 OOXML 원본 구조를 보존하는 회사 양식 어댑터를 둔다. `@xmldom/xmldom`과 JSZip으로 필요한 요소만 편집한다. ZIP 크기/구조, DTD, 외부 관계와 지원하지 않는 활성 요소를 검사한다.
- 회사 파일은 첫 등록 때 고정 요소/동적 연결을 확인한다. 미연결 값을 비우고 노트·댓글·미사용 관계를 정리한다. 고정 그림/마스터는 원본 확인 책임을 안내한다. 새 버전은 불변 ID여서 이전 작업을 바꾸지 않는다.
- PPT 표의 개별 칸과 전체 교체를 구분한다. 전체 교체는 기존 칸 수 이내로 제한한다. Excel 표는 비어 있고 병합 없는 영역에서만 확장한다. 서식 충돌이나 예상 글 넘침을 조용히 축소/덮어쓰지 않는다.
- 데이터 집계는 기존 analytics에 유지한다. verification은 원자료 기반 이벤트 스윕·별도 합산으로 비교하며 공통 날짜 파서 사용을 공개한다. 같은 함수를 두 번 호출한 값을 독립 검증으로 표현하지 않는다.
- 모든 결과가 통과하더라도 원자료 사실성·담당자 자유 문장은 확인 필요다. 결측은 검증 불가, 계산 차이는 불일치와 출력 차단이다. 출력된 Office 파일의 값/차트 캐시를 다시 읽어 전송 전 대조한다.
- 저장/내보내기/새 버전 요청은 서버에서 양식 소유권을 확인한다. 공유 출력은 원본 작업 소유자의 승인된 양식만 사용한다. 검증 화면·공유 Excel에서 원본 파일/행 단위 진단을 숨긴다.

## 기술 문서 링크
- [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html): Node 24 내장 저장소. 해당 버전에서 실험적 API이므로 Node 24 고정·업데이트 검증 필요.
- [PptxGenJS charts](https://gitbrent.github.io/PptxGenJS/docs/api-charts/): 네이티브 차트.
- [Playwright PDF](https://playwright.dev/docs/api/class-page#page-pdf): Chromium 인쇄.
- [ExcelJS](https://github.com/exceljs/exceljs): XLSX 읽기/출력.
- [총무랩](https://chongmulab.co.kr/): 업무 도구 허브 동선 참고. 브랜드·문구·인증 방식을 복제하지 않음.


## 2026-10-07 · 선택 로그인과 저장 경계

공개 포트폴리오 안내와 인증 활성 여부를 분리한다. 기존 실제 인증/DB/서버 권한 검사를 재사용하며 비로그인 체험은 유지한다. 브라우저에서 작업한 자료는 로그인·다운로드로 자동 업로드하지 않고 명시적 계정 저장으로 보관한다. 적용한 회사 양식만 함께 이전한다. 지원 도구 5개의 선택 보관은 계정과 별개로 브라우저에 유지한다. 당시 계정 비활성 결정을 변경한 것이며 신규 도구 추가는 없다.
